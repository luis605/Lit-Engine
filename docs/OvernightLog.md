## W7-3 Raycast/spatial far-and-sparse scenes
- Cause: with the default maxDistance (1e30) a miss walked 4096 grid steps and then slab-tested every occupied cell (O(cells)); in a 100k dense scene that was ~2.2 ms/ray.
- Fix (WorldRaycast.cpp, WorldSpatial.cpp, WorldSpatialParallel.cpp, World::m_cellBounds in WorldCore.cppm): the world keeps a grow-only cell-coordinate bounding box. A ray is first clipped to that box (+ margin); a miss returns after the large-entity list. Then cost is bounded by min(walk, scan): if the clipped walk (steps x layer cells) is cheaper than the occupied cell count, the DDA starts at the clip entry point and runs only to the exit (no 4096 cap); otherwise it scans the occupied cells directly (sparse huge scenes). Large/unindexed entities stay in their own small list tested once per ray (cheap sphere test, no extra index needed).
- Precision fix found by the new tests: the ray-sphere test cancelled catastrophically in float for rays of ~1e5+ units (false misses and hits 150-250 units off). The test now runs in double with a double-normalised direction. Ordering unchanged (ascending index, ties lower index).
